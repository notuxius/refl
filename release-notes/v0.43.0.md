- Relf checks for its own updates when it opens and shows a notice in the bottom status row. You can also use **More → Check for Relf updates**. **Update and restart** verifies the new executable, installs it in place, and keeps your app list and settings. If the new window fails to open, Relf restores the previous executable. Install this release manually once to start using the updater.
- The app list now shows **Close and Install** for a running app. Relf waits for it to exit before installing. If the installer and app use separate executables, set **Running app EXE** under **Edit item → General**.
- When a running app blocks an update, Relf keeps the verified download and applies it after the app exits, even if you reopen Relf in the meantime.
- Relf skips downgrades when it can compare the installed and offered versions. The check also applies to cached repairs and updates waiting for an app to close.
- Batch updates adjust concurrency to publisher responses and retry temporary failures. When GitHub rate-limits requests, Relf waits for the reset while continuing to check other publishers.
- ISO target filenames can include `{version}`. After a successful update, Relf removes the previous ISO only if its checksum matches the saved copy.
- Direct-download installers can report a version even when the server ignores range requests, provided the complete response is no larger than 32 MiB.
